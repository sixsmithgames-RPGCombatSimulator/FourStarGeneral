## Demonstrated defects and single authority

The optional/default engine API **Simple** enemy policy is not the normal new-UI enemy: the UI explicitly selects **Heuristic**, and initiative uses the existing Heuristic activation boundary. Simple still has a real engine compatibility contract. The baseline looked up a moving actor at hypothetical future path coordinates, truncating multi-step planning; enumerated only primary stack occupants; and updated placement/supply without stable stack identity. More seriously, it published a deferred pre-combat actor snapshot after canonical combat while applying movement fuel, potentially refunding ammunition, undoing retaliation damage or recreating a destroyed attacker. Its real-contact list also bypassed spotting.

The repair retains Simple's nearest-contact/deception policy, Player-opponent scope, API default and save format. It uses existing engine movement/entry/placement/supply/attack authorities, carries exact actor identity through planning and commits movement/fuel before combat. There must be no post-combat stale actor write. No alternate state ledger, AI scheduler, combat resolver or strategy alias is added. Heuristic and initiative mechanics are not being redesigned.

**Pointe du Hoc** announced that a German counterattack force emerged from the forest at turn three without observing a move or spawn. The authored force is already on the map. Phase copy now describes an advisory counterattack window, retaining its phase IDs, timing, hold/scoring mechanics, markers and save fields. Recognized saved phase IDs recover canonical current presentation, including terminal saves, without rewriting unknown phases or inventing an enemy event.

Risk and impact analysis was recorded before implementation in `implementation_plan.md`. Independent reviewers cover legality, stack identity, knowledge boundaries, combat publication order and save replay.
